### 2. 注释规范（对应你的要求 1，中文注释）
- **文件头**：每个源文件顶部用块注释说明该文件的职责（一句话）。
- **函数/方法**：导出函数、类方法、关键内部函数顶部使用 TSDoc/JSDoc 风格注释（`/** ... */`），说明用途、参数、返回值、可能抛出的错误；Android 侧对应 KDoc。
- **关键逻辑**：非显而易见的算法、协议处理（如 socket 握手、XML 控件树解析、坐标换算）、边界条件（超时、设备断开）处必须有行内注释解释"为什么"。
- **关键变量**：含义不自明的变量（如端口 `39827`、魔数、状态标志）声明处加行内注释。
- 明确反例：不写"复述代码"的废话注释（如 `i++ // i 加 1`），注释解释意图而非动作。

### 3. 单文件规模与拆分规范（对应你的要求 2）
- 单个组件/模块文件目标 **200–300 行以内**；超过 300 行必须拆分。
- 拆分策略（给出本项目实例）：

  - 主进程模块：按职责单文件单类（参考现有 `session.ts`/`agent-client.ts`/`runner.ts` 的划分方式）。
- 拆分优先级：可读性 > 复用性，不为拆而拆。

### 4. 目录结构规范（对应你的要求 3，大公司风格）
给出现状 → 目标结构演进约定，保持 electron-vite 三段式不动，在其内部按"分层 + 按域划分"组织：
```
src/
├── main/                  # 主进程
│   ├── index.ts           # 入口：窗口 + IPC 注册
│   ├── ipc/               # IPC handler（handler 增多时从 index.ts 拆出）
│   ├── services/          # 领域服务：session、agent-client、runner、adb…
│   └── utils/             # 主进程工具：hierarchy 解析等
├── preload/               # 预加载脚本（contextBridge 暴露层，保持薄）
├── renderer/src/
│   ├── components/        # 可复用 UI 组件（按域再分子目录）
│   ├── hooks/             # 自定义 Hook（use-xxx.ts）
│   ├── styles/            # 样式文件
│   └── App.tsx            # 组合层，保持薄
├── shared/                # 主/渲染进程共用
│   ├── types/             # 类型定义（增多时按域拆分）
│   └── utils/             # 纯函数（task 校验、坐标换算…）
├── android/               # 独立 Gradle 工程（不动其结构）
├── scripts/               # 构建/发行脚本
├── tests/                 # Vitest 测试，与被测模块同名
└── assets/ examples/      # 资源与示例
```
- 原则：按"层"先于按"类型"组织；同域文件就近放置；新增目录需在 AGENTS.md 中登记职责。

### 5. 命名规范（对应你的要求 4）
- **文件名**：全部小写 kebab-case：`agent-client.ts`、`stage-agent.mjs`、`use-device-session.ts`；组件文件同样 kebab-case（如 `device-panel.tsx`）；测试文件 `xxx.test.ts`。
- **代码标识符**：类/组件 PascalCase（`DeviceSession`、`TaskRunner`）；函数/变量 camelCase；常量 UPPER_SNAKE_CASE（`AGENT_PORT`）；类型/接口 PascalCase。
- **语义化 + 克制长度**：名字表达用途，避免缩写和黑话；标识符一般不超过 4 个单词（如 `refreshSnapshot` 优于 `handleRefreshDeviceSnapshotData`）。
- 保留现有约定：UI 文案与错误信息使用中文。
