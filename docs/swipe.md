# 比例滑动

普通步骤与条件分支使用相同的滑动配置，仅支持以下两种方式：

| 方式 | 比例基准 | 使用建议 |
| --- | --- | --- |
| 屏幕比例 | 执行时当前方向的完整手机屏幕 | 整体页面滑动 |
| 控件内比例 | 执行时目标控件边界与屏幕区域的交集 | 列表、局部滚动区域 |

坐标以区域左上角为起点，X 向右增加，Y 向下增加，百分比范围为 0–100，支持小数。默认从 `(50%, 80%)` 滑到 `(50%, 20%)`，手指向上移动，时长为 500 毫秒。方向始终指手指移动方向。切换两种方式会保留比例路径；控件定位单独配置，可使用当前拾取结果或手动填写，支持可选匹配序号。

控件不必标记为可滚动，但应选择实际响应手势的区域。系统栏、键盘、弹窗遮挡和页面布局改变仍可能影响手势效果；屏幕比例不会自动扣除系统栏和键盘。相同百分比与时长不保证滑过相同条数，也不保证某个目标出现。查找目标可组合已有条件判断与有限次数的重复滑动。

## 任务格式

屏幕比例示例：

```json
{
  "version": 1,
  "name": "按屏幕比例滑动",
  "steps": [{
    "id": "swipe-1",
    "type": "swipe",
    "coordinateMode": "screenPercent",
    "from": { "x": 50, "y": 80 },
    "to": { "x": 50, "y": 20 },
    "durationMs": 500
  }]
}
```

控件内比例将 `coordinateMode` 改为 `elementPercent`，同时添加：

```json
{
  "container": { "kind": "resourceId", "value": "com.example:id/list" },
  "timeoutMs": 10000
}
```

任务版本仍为 1。滑动必须明确填写比例模式，旧的像素滑动格式不再接受，需重新配置。百分比起终点不能相同；时长须为 100–10000 毫秒，控件查找超时须为 100–60000 毫秒。其他任务大小和步骤数限制保持原有约束。

## 执行与日志

桌面端发送 `swipeRelative`，手机端实时获取屏幕尺寸和目标区域；100% 映射到区域最后一个有效像素。控件缺失、匹配有歧义、区域不可见、像素路径重合、注入前方向或尺寸改变、手势未完成都会明确失败。日志保存模式、配置路径以及手机确认完成后的实际区域和像素起终点。不支持命令的旧代理会提示更新，不会尝试用旧坐标执行。

开发时重新构建两个 Android APK 后执行 `npm run stage:agent`。ADB 连接时会安装更新的 APK；手机直连需要更新手机端应用。

## 验证

- 桌面端：`npm test`、`npm run build`。
- Android：在 `android/` 运行 `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest`。
- 实机：在两台不同分辨率和屏幕比例的手机上运行相同任务，分别验证屏幕与局部列表的滑动位置。
- 两类连接均验证控件缺失、重复匹配、部分区域移出屏幕、横竖屏和执行前转屏；失败时检查后续步骤停止且日志保留步骤或分支位置。
- 编辑器直接填写起终点和时长，方向由起终点确定。验证比例微调、模式切换、匹配序号、条件分支及任务导入导出；旧像素任务应提示重新配置。
